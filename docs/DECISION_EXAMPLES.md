# Decision explanation examples

These examples use the checked-in workflow configurations. Actual rule traces and timestamps are generated by the API for each request.

## 1. Loan approved

**Input:** applicant `APP-100`, monthly income `60000`, credit score `720`, requested amount `500000`.

| Rule | Evaluation | Outcome |
|---|---|---|
| `income_minimum` | 60000 >= 30000 | PASSED |
| `credit_score_minimum` | 720 >= 650 | PASSED |
| `loan_amount_limit` | 500000 <= 1000000 | PASSED |
| `credit_bureau` | simulated verification | SUCCESS |

**Decision:** `APPROVED`.

**Explanation:** All configured business rules passed and the external verification dependency succeeded.

## 2. Loan rejected

**Input:** same as above, but credit score `600`.

| Rule | Evaluation | Outcome |
|---|---|---|
| `income_minimum` | 60000 >= 30000 | PASSED |
| `credit_score_minimum` | 600 >= 650 | FAILED |
| `loan_amount_limit` | Not evaluated after terminal failure | SKIPPED |

**Decision:** `REJECTED`.

**Explanation:** The request was rejected because the credit score must be at least 650. The external dependency is not called after a business-rule rejection.

## 3. Loan sent for manual review

**Input:** same as approved example, but requested amount `1500000`.

| Rule | Evaluation | Outcome |
|---|---|---|
| `income_minimum` | 60000 >= 30000 | PASSED |
| `credit_score_minimum` | 720 >= 650 | PASSED |
| `loan_amount_limit` | 1500000 <= 1000000 | FAILED |

**Decision:** `MANUAL_REVIEW`.

**Explanation:** The request requires human review because the requested amount exceeds the automatic approval limit. No external dependency call is needed for a request already routed to review.

## 4. Dependency retry and recovery

Submit an otherwise eligible loan with `simulation_mode: "transient_then_success"` and a fresh idempotency key. The first simulated call fails transiently, the retry is recorded, and the next attempt succeeds.

**Decision:** `APPROVED` after 2 attempts. The audit endpoint exposes `DEPENDENCY_FAILED`, `RETRY_SCHEDULED`, `DEPENDENCY_SUCCEEDED`, state transitions, and both retry records.

## 5. Dependency failure

Submit an eligible loan with `simulation_mode: "timeout"`. The loan configuration allows 3 attempts.

**Decision:** `FAILED` after 3 transient failures. Each attempt and retry scheduling event is present in the audit history. Permanent failure mode is attempted once and is not retried.

## 6. Manual review resolution

**Input:** an eligible loan with requested amount `1500000`, or a `MANUAL_REVIEW` request from any workflow, plus:

```json
{"decision": "APPROVED", "reviewer": "ops-1", "notes": "Income documents verified."}
```

| Step | Recorded outcome |
|---|---|
| Initial evaluation | `loan_amount_limit` FAILED, decision `MANUAL_REVIEW` |
| Review API | `REVIEW_DECIDED` audit event with reviewer and notes |
| State transition | `MANUAL_REVIEW → APPROVED` |
| Final explanation | "Manual review by ops-1 resulted in APPROVED. Notes: Income documents verified." |

A second review attempt returns `409 Conflict`. The reviewer decision is authoritative; the external dependency is not re-run during manual resolution.

## 7. Composite conditional rule (insurance claim)

**Input:** claim `CLM-2`, active policy, amount `50000`, incident `1` day ago, documents complete.

| Rule | Evaluation | Outcome |
|---|---|---|
| `active_policy` | active = true | PASSED |
| `incident_reporting_window` | 1 <= 30 | PASSED |
| `standard_timeline_and_value` | all(1 >= 3, 50000 <= 150000) | FAILED |
| `documents_complete` | Not evaluated after terminal failure | SKIPPED |

**Decision:** `MANUAL_REVIEW`.

**Explanation:** Claims reported within 2 days or above INR 150,000 require expedited manual review. The trace records both sub-conditions and the `match: "all"` grouping, so the reviewer can see exactly which condition failed.
